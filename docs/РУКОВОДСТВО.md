# VDS Admin — руководство пользователя

Как запустить программу, добавить серверы и сайты и разобраться в том, что она
показывает.

Остальные документы в `docs/` написаны для разработчика и на английском. Этот — для того,
кто пользуется программой.

---

## 1. Запуск

### Из собранного проекта

```bash
cargo run -p vds-admin
```

Если команда `cargo` не находится, откройте новый терминал: переменные окружения
прописаны, но уже запущенный терминал их не подхватил.

### Из готового файла

Windows — `vds-admin.exe`, двойной клик. Linux — `.AppImage` или пакет `.deb`. macOS —
`.dmg`. Ничего настраивать перед первым запуском не нужно: программа сама создаст базу
данных и файл настроек.

### Посмотреть, как выглядит с данными

Если серверов ещё нет, а хочется увидеть заполненный интерфейс:

```bash
cargo run -p vds-admin --features demo-providers
```

Это режим разработки. Данные в нём **выдуманные** — провайдер так и называется, «Demo
(fabricated data)». В обычной сборке его нет вообще.

---

## 2. Первый экран

При первом запуске всё пусто, и это правильно: программа ничего не знает о ваших
серверах, пока вы их не добавите.

Слева — разделы. На узком экране они переезжают вниз.

| Раздел | Что там |
|---|---|
| **Сводка** | Общая картина: сколько серверов в сети, сколько сайтов отвечает, средняя нагрузка, последние события |
| **Серверы** | Список машин и подробности по каждой |
| **Сайты** | Список сайтов со скриншотами и подробности |
| **Аналитика** | Трафик по всем сайтам сразу |
| **Оповещения** | Что сработало и по каким правилам |
| **Настройки** | Тема, язык, уведомления, аналитика, хранилище |

## 3. Добавить сервер

**Серверы → Добавить сервер.**

Есть два способа подключения. Начните с SSH — на сервер ничего ставить не надо.

### 3.1 По SSH

| Поле | Что вписать |
|---|---|
| **Название** | Как вам удобно видеть его в списке: `prod-web-01` |
| **Хост** | IP-адрес или имя: `10.0.0.5` или `web01.example.com` |
| **Подключение** | SSH (агент не нужен) |
| **Порт** | 22 |
| **Пользователь** | Учётная запись на сервере. Лучше отдельная, не root |
| **Аутентификация** | Пароль, Приватный ключ или Зашифрованный приватный ключ |
| **Пароль / Приватный ключ** | Пароль, либо ключ целиком — вместе со строками `BEGIN` и `END` |
| **Парольная фраза** | Появляется, только если выбран зашифрованный ключ |
| **Опрашивать раз в** | Секунды. 30 — разумное начало |

Нажмите **Добавить**. Первый сбор данных пойдёт сразу, поэтому строка появится уже с
цифрами, а не с прочерками.

**Куда попадёт пароль.** В системное хранилище учётных данных Windows (Credential
Manager), в базе останется только ссылка. В файлах программы пароля нет ни в каком виде.

**Что нужно на сервере.** Обычный шелл и стандартные утилиты — `df`, `ps`, чтение
`/proc`. Устанавливать нечего.

Две вкладки требуют большего:

- **Docker** — учётная запись должна входить в группу `docker`. Учтите: это равносильно
  правам root на той машине. Не хотите — вкладка просто покажется недоступной, всё
  остальное будет работать.
- **Службы** — работает на любой системе с systemd, дополнительных прав не нужно.

**Совет по безопасности.** Заведите на сервере отдельного пользователя и ограничьте ключ
адресом вашего компьютера — тогда украденный ключ бесполезен с чужой машины:

```sh
sudo useradd --system --create-home --shell /bin/sh vds-monitor
```

В его `~/.ssh/authorized_keys`:

```
from="10.0.0.5",no-agent-forwarding,no-port-forwarding,no-pty ssh-ed25519 AAAA... vds-admin
```

### 3.2 Через агент

Нужен, когда серверов сотни (SSH-рукопожатие на каждый опрос становится дороже самих
данных) или когда SSH-доступ давать не хочется. Агент умеет только отдавать показания —
ничего запускать и менять на сервере он не может.

Сначала установите его **на сервере**:

```bash
curl -fsSL https://github.com/vds-admin/vds-admin/releases/latest/download/install.sh | sudo sh
```

Установщик проверит контрольную сумму до распаковки, создаст непривилегированного
пользователя, запустит службу и напечатает две вещи:

```
  Token: k3Jd8vQ2mN7pX1aY6bZ4cR9eT5wU0iO8sL2fH6gK4jM=
  Fingerprint: 3C:F2:...:9A
```

Потом в программе: **Серверы → Добавить сервер**, **Подключение → Агент (HTTPS)**, порт
9443, и вставьте токен.

**Обязательно сверьте отпечаток.** При первом подключении программа покажет отпечаток
сертификата — он должен совпасть с тем, что напечатал установщик. Это работает как ключ
хоста в SSH: программа запоминает его и предупредит, если он изменится. Не совпал —
значит между вами и сервером кто-то есть, соглашаться нельзя.

Прочитать оба значения потом:

```bash
sudo cat /etc/vds-agent/token
sudo vds-agent --fingerprint --config /etc/vds-agent/agent.toml
```

Подробнее — [AGENT.md](AGENT.md) (на английском).

### 3.3 Что дальше с сервером

Кликните по строке — откроются вкладки:

| Вкладка | Что показывает |
|---|---|
| **Обзор** | ЦП, память, диск, аптайм, сведения о системе |
| **Метрики** | Графики за 1 час … 90 дней |
| **Процессы** | Топ по загрузке ЦП |
| **Службы** | Юниты systemd, в том числе упавшие |
| **Docker** | Контейнеры: образ, состояние, потребление, перезапуски |
| **Сайты** | Сайты, привязанные к этому серверу |
| **События** | Что с ним происходило |
| **Настройки** | Забыть ключ хоста, удалить сервер |

Пустая вкладка и недоступная вкладка — разные вещи. «На этом хосте нет Docker» означает,
что Docker не установлен, и это не считается неисправностью. Если Docker есть, но
контейнеров нет, будет написано именно так.

**Удаление** — вкладка «Настройки», в два шага. Удаляются сервер, его учётные данные и
история метрик. Сам сервер не трогается: на нём ничего не установлено.

**Забыть ключ хоста** нужен только после переустановки сервера или смены его ключей.
Сверьте новый отпечаток перед повторным подключением.

## 4. Добавить сайт

**Сайты → Добавить сайт.**

| Поле | Что вписать |
|---|---|
| **Название** | `Сайт компании` |
| **Адрес** | `example.com` — если схему не указать, подставится `https://` |
| **Проверять раз в** | Секунды. 60 — обычно достаточно |
| **Ожидаемый код** | 200 |
| **Ожидаемый текст** | Необязательно: подстрока, которая должна быть на странице |

Про ожидаемый текст: если оставить пустым, проверяется только код ответа. Пустое
ожидание совпало бы с любым ответом — проверка выглядела бы успешной и не проверяла бы
ничего, поэтому пустое поле означает «не проверять текст».

Что проверяется на каждом цикле: DNS, TCP-соединение, код HTTP, время ответа, срок
действия и издатель TLS-сертификата.

Скриншот страницы делается, если в системе есть браузер на основе Chromium (Chrome, Edge,
Brave). Нет браузера — карточка будет без картинки, всё остальное работает. Скриншот
всегда подписан временем съёмки: «Снято 4 ч назад». Старая картинка никогда не выдаётся
за текущую.

## 5. Оповещения

Семь правил создаются при первом запуске:

| Правило | Когда срабатывает |
|---|---|
| ЦП выше 90 % | и держится так 5 минут |
| Память выше 95 % | |
| Диск выше 90 % | |
| Сервер не в сети | после трёх неудачных проверок подряд |
| Сайт не отвечает | |
| Сертификат истекает | меньше чем через 14 дней |
| Контейнер Docker остановлен | |

Пять минут у правила по ЦП — не формальность: без выдержки одна пиковая секунда во время
сборки или бэкапа поднимала бы тревогу каждый раз.

На экране «Оповещения» их можно включать и выключать, а сработавшие инциденты —
принимать (кнопка «Принять»), чтобы они не напоминали о себе повторно.

**Создать своё правило из интерфейса пока нельзя.** Пороги правятся в файле настроек —
см. раздел 7.

Уведомления на рабочем столе включаются в **Настройки → Уведомления**. Там же — адрес
вебхука, если нужно отправлять события во внешнюю систему.

## 6. Настройки

| Раздел | Что можно |
|---|---|
| **Внешний вид** | Тема: светлая, тёмная, как в системе. Язык: русский, английский — применяется сразу |
| **Уведомления** | Уведомления на рабочем столе, звук, адрес вебхука |
| **Аналитика** | Номер счётчика Яндекс.Метрики и OAuth-токен |
| **Скриншоты** | Как часто обновлять: каждый час, раз в 6 часов, раз в сутки, вручную |
| **Хранилище учётных данных** | Куда попадают пароли и токены |
| **Хранение и диагностика** | Путь к базе, её размер, путь к журналам, режим отладки |

Обратите внимание на строку **Хранилище**. Если там системное хранилище — хорошо. Если
написано, что используется зашифрованный файл, значит системное хранилище на этой машине
недоступно; данные зашифрованы, но системное хранилище надёжнее.

## 7. Где лежат данные

```
C:\Users\<вы>\AppData\Roaming\vds-admin\
├── vds-admin.db        серверы, сайты, история метрик, инциденты
├── config.toml         пороги, интервалы, сроки хранения
├── logs\               журналы, ротация посуточно
└── screenshots\
```

На Linux — `~/.local/share/vds-admin/`, на macOS —
`~/Library/Application Support/vds-admin/`.

Удалить папку — начать с чистого листа. Пароли лежат отдельно, в системном хранилище, и
это переживут.

`config.toml` правится вручную, программа при этом должна быть закрыта. Там задаются
пороги ЦП, памяти и диска, интервалы опроса по умолчанию и сроки хранения метрик (по
умолчанию: подробные данные 7 дней, пятиминутные 30 дней, часовые год).

## 8. Если что-то не работает

**«Аутентификация не удалась».** Неверные пользователь, ключ или парольная фраза, либо
ключ не добавлен в `authorized_keys`. Проверьте на сервере:

```bash
sudo journalctl -u ssh -n 50
```

Частая причина — права: `sshd` отвергает ключ, если каталог `~/.ssh` не `700`, а файл
`authorized_keys` не `600`.

**Сервер помечен как «Не в сети», хотя он работает.** Одна неудачная проверка — это
предупреждение, а не авария. «Не в сети» появляется после трёх подряд неудач. Проверьте
руками:

```bash
ssh пользователь@хост 'df -PkT; ps -eo pid,user,pcpu,pmem,rss,args | head'
```

Если так работает, а программа не может — дело в подключении, а не в командах.

**Вкладка пустая.** На странице сервера написано, какие сборщики не отработали и почему.
«Не поддерживается» означает, что на хосте нет такой возможности — это не поломка.

**Ничего не понятно.** Включите **Настройки → Режим отладки**: журналы станут подробнее,
в них попадут все команды и коды возврата. Пароли, ключи и токены из журналов вырезаются
на трёх независимых уровнях, поэтому журнал можно безопасно кому-то показать.

## 9. Чего пока нет

Честный список, чтобы вы не искали то, чего не существует:

- **Управление контейнерами и службами** — запуск, остановка, перезапуск, просмотр
  логов. Программа спроектирована под это, но такая возможность меняет цену украденных
  учётных данных, поэтому она ждёт подтверждений действий и журнала аудита.
- **Создание своих правил оповещений из интерфейса.** Готовые семь включаются и
  выключаются; новое правило пока не создать.
- **Редактирование добавленного сервера.** Поменять интервал или учётные данные можно
  только удалив и добавив заново, а это теряет историю метрик.
